# User requirements

| Id | Requirement |
|---|---|
| URS-01 | A change to a regulator's site that breaks extraction is detected before the crawl's data is used. |
| URS-02 | While a source is broken, production keeps the last data that passed the contract. |
| URS-03 | A repaired scraper reaches production only after automated checks on every page the site serves and a review. |
| URS-04 | When the site's content really changed, the incident goes to a person instead of becoming a code change. |
| URS-05 | The repair agent cannot see the truth or act outside its sandbox. |
| URS-06 | Each clause change is classified editorial or substantive from what the obligation says. |
| URS-07 | Every requirement proposed as affected cites evidence, and the evidence is checked. |
| URS-08 | Devices that a change brings into scope without a requirement are reported as gaps. |
| URS-09 | An assessment counts only when an authorised person signs it, and the signature binds to its content. |
| URS-10 | The record of crawls, repairs, assessments and signatures is tamper-evident. |
| URS-11 | A restarted run does not repeat crawls or repairs. |
| URS-12 | Nothing that makes a decision reads the simulator's truth. |
| URS-13 | The console works with a keyboard and assistive technology, in light and dark. |
